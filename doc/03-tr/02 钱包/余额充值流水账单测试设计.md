# 测试范围

余额、面额、充值下单（微信/支付宝）、dev 入账、流水 product、月账单、S2S 扣款/入账/幂等、支付宝异步通知验签。

# 测试用例

| 编号 | 前置 | 步骤 | 预期 | 自动化 |
|:---|:---|:---|:---|:---|
| W1 | 已登录 | GET balance / presets | 返回数值与面额列表 | 手工 |
| W2 | RECHARGE_DEV_AUTO=1 | `/mgr/` 下单 → dev-pay | 余额增加，流水 type=recharge product=mgr biz_type=recharge_dev | 手工 |
| W3 | 已 paid 单 | 再次入账 | 幂等，余额不变二次加 | 手工 |
| W4 | S2S key 正确 | deduct 足额 product=vf biz_type=consume_voice | 余额减，流水含 product+biz_type | 手工 |
| W4b | S2S | deduct 缺 biz_type 或 product=voice | 400 | 手工 |
| W5 | 余额不足 | deduct | 400 | 手工 |
| W6 | 错误 S2S key | deduct | 401 | 手工 |
| W7 | 有消费 | GET bills | 当月汇总出现 | 手工 |
| W8 | ALIPAY_ENABLED=1 且密钥齐全 | GET pay-channels；POST recharge `channel=alipay` | channels 含 alipay；返回 `pay_url` 或 `code_url` | 手工 |
| W9 | 支付宝沙箱/真实小额 | 支付成功后异步通知 | 订单 paid，`payment_channel=alipay`，余额增加 | 手工 |
| W10 | 伪造支付宝通知签名 | POST notify/alipay | 非 success，订单仍 pending | 手工 |
| W11 | 控制台已开双渠道 | 充值区：先选支付大卡片，再选面额/输入金额点充值 | 渠道卡片在上、面额为大按钮；下单 `channel` 与所选一致 | 手工 |
| W12 | 宽屏桌面打开 `/mgr/wallet` | 查看余额与充值卡片宽度 | 内容列约 ≤480px，右侧有留白，渠道按钮未横向拉满 | 手工 |
| W13 | 微信或支付宝已启用 | `/mgr/` 充值下单成功 | 支付码与提示在 Modal 内，充值卡片正文无二维码 | 手工 |
| W14 | 同上 | `/cert/`、`/vf/` 账户充值下单 | 与 mgr 同为弹窗扫码；弹窗内有二维码图 | 手工 |

# 自动化测试标识

默认不强制；微信/支付宝回调用沙箱或小额手工验签。

# 背景

证书控制台（hipp-https）、语音修复（VoiceFix）、需求分析（hipp-or）各自或挂靠对方做登录与扣费，导致同一手机号多套口令、充值入口分散、微信支付逻辑重复。需要一个独立平台工程统一管身份与余额钱包，业务系统只做本产品能力。

# 目标

1. 提供跨产品统一的手机号登录、资料与改密能力。
2. 提供跨产品共享余额、充值、支付、充值订单与流水账单。
3. 微信支付 Native、支付宝收款只在本工程实现一次，业务系统不得再自建支付入账。
4. VoiceFix、hipp-or、hipp-https 的身份与钱包能力全部切到本工程；VoiceFix 去掉会员档位（会员制不迁入）。

# 要求

## 功能性

1. 支持短信验证码登录（未注册自动建号）与密码登录；支持短信重置密码；建号须写入注册来源产品码 `register_source`（`mgr`/`or`/`vf`/`cert`）。
2. 支持查看与修改昵称、设置/修改登录密码。
3. 支持查询余额、充值面额、发起微信扫码 / 支付宝充值、查询充值单状态与充值订单列表；充值单与入账流水的 `product` 为**实际充值入口产品**（如在 `/mgr/` 充值则为 `mgr`），并带 `biz_type`（如 `recharge_wechat`）。
4. 支持分页查询交易流水；流水必须带产品标识（`mgr` / `or` / `vf` / `cert`，可扩展）及业务类型子类 `biz_type`。
5. 支持按月查看消费账单汇总。
6. 提供服务间接口：按手机号或用户 ID 查询余额、扣款、入账（带产品与业务单号）。
7. 本工程提供独立账户控制台（登录、资料、改密、余额、充值、流水、账单、订单）。
8. VoiceFix 仅保留语音业务与按分钟扣费（统一费率）；充值/支付/订单/身份一律走本工程。
9. hipp-or 用户侧短信/密码登录走本工程；管理端员工账号可暂留本地。
10. 支付宝：公钥模式 RSA2；异步通知验签后入账；账单/流水与微信共用同一套钱包表。

## 非功能性

1. 口令不明文存储；会话令牌有过期时间。
2. 充值仅在支付确认后入账；微信与支付宝回调均须验签。
3. 服务间接口须密钥鉴权；VoiceFix 须配置 `HIPP_MANAGER_BASE`+`HIPP_MANAGER_KEY` 方可计费扣款。
4. 不把 VoiceFix 会员档位体系迁入本工程，并在 VoiceFix 侧下线会员开通/续费/升级。
5. 跨产品以手机号对齐，登录时按需在本工程建号；生产环境须使用 MySQL（勿用 SQLite 作生产库）。
6. 同一站点（如 `hipp.site`）下各产品登录态须互通：任一产品登录后，其它产品（`/mgr/`、`/or/`、`/cert/`、`/vf/`，以及 or 管理端 `/or/manager/`）再访问须视为已登录，无需重复登入；任一产品退出后，其它产品再访问须回到未登录；本服务须支持主动吊销会话令牌。
7. 上线时须能从既有库按手机号整合：hipp-or 用户（口令/昵称）与 VoiceFix（`voicefix.user`）资金余额并入本工程用户表；不整库物理搬迁业务表。
8. 「用户是否在线」以本工程会话为准：hipp-https、hipp-or（Web/管理端）、VoiceFix 凡需鉴权的业务接口，须由**各产品后端**向本工程校验会话（如 `GET /api/auth/me`），不得仅凭本产品本地令牌判定在线；前端不单独申请在线状态。or 微信登录与 `mp_guest` 不在此列（本工程不做微信登录）。
9. 账户控制台中控件较少的表单/充值区应限制内容列宽、允许右侧留白，勿横向撑满主内容区；流水与账单等宽数据区可全宽。
10. 充值下单后展示支付二维码与扫码提示须用**弹窗（Modal）**，不得把二维码嵌在充值页正文流内；微信、支付宝及其他走本钱包的付款入口（mgr / vf / cert）交互一致。

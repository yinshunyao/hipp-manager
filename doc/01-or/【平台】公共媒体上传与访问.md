# 背景

1. 各产品（or / vf / cert / mgr）均有用户侧文件上传需求（对话附件、头像、凭证等）；若各自接 OSS 或本地盘，会出现配置分散、密钥重复、URL 不可达等问题。
2. hipp-or 对话多模态曾直连本产品内的阿里云 OSS 占位配置，生产易出现 endpoint/bucket 未落地导致上传失败；附件又须被 Dify 以 `remote_url` 公网拉取。
3. 本工程已预留 `data/media/` 数据目录，适合作为平台级媒体主存与对外访问入口。

# 目标

1. 在 hipp-manager 提供跨产品共用的媒体上传与公网可读访问能力。
2. 各产品业务后端（或受控前端）经本服务鉴权后上传，拿到可被第三方（如 Dify）HTTP GET 的绝对 URL。
3. 降低业务产品对阿里云 OSS 直连配置的依赖；首期以本机目录存储即可稳定联调与上线。

# 要求

## 功能性要求

- **上传**：已登录用户（平台 Bearer）可 `multipart` 上传单个文件；须携带 `product`（产品码白名单）；可选业务路径前缀（如 `chat`）。
- **落盘**：写入本服务 `data/media/`（或可配置根目录）；对象键含 `product`、用户标识、日期与不可猜测文件名。
- **访问**：对外提供稳定路径前缀（建议 `/media/...`），返回**绝对 URL**（依赖可配置的公网基址），供历史展示与 `remote_url`。
- **鉴权**：上传须平台用户会话；读文件首期可公开（依赖不可猜测路径），不做目录列举。
- **限额**：平台单文件上限可配置（默认与对话附件量级对齐，如 ≤20MB）；更严的类型/个数限制由调用方产品自行校验。
- **用户删除**：已登录用户可删除**本人路径下**的媒体（按 `path` 或绝对 `url`）；用于「上传后未发送即从待发列表移除」等场景，须真正删盘。
- **服务间删除**：产品后端可用 S2S 批量按 URL/path 删除（须带产品码），供「话题结束清理」等业务策略执行。
- **清理策略（由产品驱动）**：平台不解析「方案」语义；不自动按会话结束扫盘。哪些 URL 可删由调用方判定后调删除接口。
- **孤儿扫盘（S2S）**：提供按产品/前缀扫盘接口；删除「早于宽限期且不在保留 URL 集合中」的文件。定时触发与保留集收集由产品（如 or）负责。

## 非功能性要求

- 不在文档与代码默认值中写入真实 AccessKey、客户路径。
- Nginx / 网关须放行上传体大小与 `/media/`（或等价）静态访问；Dify 出口须能 GET 到返回的 URL。
- 首期不做对象存储后端；若后续接 OSS，应对调用方保持同一上传/URL 协议。
- 删除已不存在的对象视为成功（幂等）。

## 明确不做（本版）

- 客户端直传第三方对象存储 STS；目录浏览 API；按文件 ACL 细粒度授权；音视频转码。
- 平台进程内自启全站定时器（无业务库无法判定引用）；定时在 or 等产品侧。

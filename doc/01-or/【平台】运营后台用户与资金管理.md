# 背景

跨产品身份与钱包已收口到 hipp-manager，但用户拉黑/改密、流水与充值单查询、手工入账与退费仍分散在 hipp-or 管理端与 VoiceFix Django Admin。运营需要统一入口；业务审批（任务取消、申诉等）仍应留在各产品后台，批准后只调本工程动账。平台管理员希望一套账号能登录各产品管理端。

# 目标

1. 在本工程提供运营台，统一管理平台用户与资金流水、充值单、手工动账。
2. 用 CLI 维护平台管理员账号，供本运营台及 or / vf / cert 等产品管理端共用校验。
3. 充值、流水、注册来源均按实际产品码划分，资金记录另带业务类型子类。

# 要求

## 功能性

1. 平台管理员独立于普通用户；新建与命令行重置均使用初始密码 `123456`，登录后由管理员自行改密；命令行只做创建账号与重置回初始密码（不设自定义口令）；首期不做细粒度 RBAC（仅「是否平台管理员」）。
2. 运营台路径与用户账户台分离（`/mgr/manager/`，与各产品 `/{product}/manager/` 约定一致）：支持用户列表（含注册来源）、拉黑/解黑、运营改密；流水与充值单按 `product` / `biz_type` 筛选；手工入账与退费须填 `product`、`biz_type`、备注。
3. 提供管理员登录与校验接口，供 or / vf / cert 管理端密码登录时校验同一套平台管理员（校验失败可回落各产品本地员工逻辑）。
4. or 用户管理中的列表/拉黑/来源等运营能力以本工程为准；or 角色/菜单/智能体等业务配置仍留 or。
5. vf 用户余额/流水/手工结案以本工程为准；任务取消与申诉等业务审批留 vf，批准后 S2S 入账并传正确 `product`+`biz_type`。
6. 产品码仅 `mgr` / `or` / `vf` / `cert`（可扩展）；禁止 `manager` / `voice`。全局约束见 `.cursor/rules/rules-hipp-product-codes.mdc`。

## 非功能性

1. 运营接口须管理员会话；普通用户令牌不可访问。
2. 手工动账须可审计（操作者标识写入备注或独立字段）。
3. 存量流水产品码一次性迁移：`manager`→`mgr`，`voice`→`vf`。

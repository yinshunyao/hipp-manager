# 功能设计

## 用户模型

- 表 `user`：`user_id`（UUID）、`phone`（唯一）、`nickname`、`password_hash`（≤255）、`has_password`、`avatar_path`、`balance`、`created_at`。
- 无数据库外键；跨产品用 `phone` 对齐。
- **生产**：`DATABASE_URL=mysql+pymysql://.../hipp_manager`（独立库，与 `hipp` / `voicefix` 同实例）；开发可空则 SQLite。
- **存量整合**（一次性 `python -m manager.import_legacy`）：
  1. 从 `voicefix.user` 取 `phone/nickname/password_hash/balance/avatar_path/user_id`。
  2. 从 `hipp.vadmin_auth_user`（`is_delete=0`）取 `telephone/nickname|name/password/avatar`。
  3. 按手机号合并：余额以 VoiceFix 为准（无则 0）；口令优先 VoiceFix `has_password`，否则用 or 的 bcrypt；`user_id` 优先沿用 VoiceFix。
  4. 已存在同手机号则更新昵称/口令/余额（余额取较大值，避免覆盖更高余额）。

## 登录

1. `POST /api/auth/sms/send`：校验手机号，写入 Redis 验证码（TTL 由 `MANAGER_SMS_VALID_TIME`）；`SMS_MOCK=1` 时固定码 `123456` 且不调阿里云。
2. `POST /api/auth/sms/login`：校验验证码；用户不存在则建号（无密码）；签发本服务 HMAC Bearer。
3. `POST /api/auth/login`：手机号 + 密码（bcrypt）；未设密码返回明确错误。

会话载荷同形于 hipp-https：`expires.phone.hmac`，密钥 `MANAGER_SESSION_SECRET`，默认 12 小时。签发后写入 Redis 白名单（键 `mgr:tok:{sha256}`，TTL 同会话）；无 Redis 时用进程内字典。`session.read` 须白名单仍有效。

- `POST /api/auth/logout`：Bearer 吊销当前令牌（删白名单）。
- 同站产品（`/mgr/`、`/or/`、`/or/manager/`、`/cert/`、`/vf/`）登录态互通约定：
  1. 浏览器同源共享键 `hipp_manager_token`：任一方登录成功后写入本服务签发的 Bearer；账户页 `/mgr/` 直接用该键调用 `/api/`。
  2. 业务产品登录接口在签发本产品会话的同时，须把 manager `token` 返回给前端（字段 `manager_token`），由前端写入 `hipp_manager_token`。
  3. 业务产品启动时若无本产品会话但存在有效 `hipp_manager_token`，调用本产品 `POST .../auth/sso`（`Authorization: Bearer <manager_token>`）换发本产品会话；换票须向 manager `GET /api/auth/me` 校验令牌。or 用户端与管理端共用 `POST /auth/sso`；VoiceFix 为 `POST /api/v1/auth/sso`。
  4. 退出：`hipp.sso.logout_at` 广播；各前端登录时记 `hipp.sso.login_at.<产品>`，并刷新共享 `hipp.sso.session_at`；启动时若 `logout_at >= max(session_at, login_at.<产品>)` 则清本地会话（含 `hipp_manager_token`）。禁止仅因「本产品从未登录 / login_at 为空」且存在历史 `logout_at` 就清掉其它产品刚写入的共享令牌。
  5. VoiceFix Django Admin（`/vf/admin/`）为服务端 Session，不走本 SPA 共享令牌约定（本轮不强制互通）。

## 资料与改密

- `GET /api/auth/me`：返回 `user_id`、`phone`、`nickname`、`has_password`、`balance`。
- `PATCH /api/auth/me`：更新昵称（≤50 字）。
- `POST /api/auth/password`：若已有密码须校验旧密码；首设可无旧密码。

## 与业务系统

- 业务产品（hipp-https、hipp-or Web/管理端、VoiceFix）可继续签发**本产品本地会话**，仅用于绑定本地用户与产品内权限（如 or RBAC、vf Redis `user_id`）。
- **在线权威为本服务会话**：登录/SSO 成功后，产品须在服务端缓存本服务 `manager_token`；凡需鉴权的业务接口，产品后端在验过本地会话后，须再调 `GET /api/auth/me`（允许按 token hash 短缓存约 30s；失败不长缓存）。manager 吊销、过期或不可达时，产品须对客户端返回 401。
- 前端只带本产品 `Authorization`；不单独调用「在线探测」接口向 manager 申请状态（产品已有的 `/auth/me`、vf `session/online` 由后端内部完成二次校验）。
- hipp-https：资料/钱包经控制台后端代理 manager。
- hipp-or：微信登录与 `mp_guest` 仍用本地 JWT，不二次校验 manager。配置了 `HIPP_MANAGER_BASE` 时，Web 短信/密码登录（含管理端）必须拿到 `manager_token`，否则登录失败。
- VoiceFix：本地 Redis Bearer 鉴权时同步校验缓存的 manager 令牌；`session/online` 表示本地会话且 manager 仍有效。

# 约束与边界

- 不实现微信登录、邮箱登录。
- 不在本服务保存业务侧业务配置（证书、语音任务等）。
- 不要求业务产品去掉本地会话；不以 `hipp_manager_token` 直接替换各产品 `Authorization`（避免拆掉 or RBAC 与 vf 用户绑定）。
